# 界面与交互规格

版本v0.1。中文原生SwiftUI；系统字体/SF Symbols、系统深浅色，不使用CleanMyMac素材、截图或品牌图标作为应用资源。原观察只用于功能组织参考。

## 1. 主窗口

设计最小尺寸1000×680 points，默认1180×780；侧栏约180–220，中间列表可伸缩，详情约300–360，可收起。不能让主要动作悬在窗口外，所有测试尺寸均能看到底部操作。

```text
┌ Local Mac Cleaner ─────────────────────────────────────────────┐
│ 空间总览 │ 扫描范围：Macintosh HD / 用户目录        [选择范围]   │
│ 清理候选 │ 可用空间  …    已知占用 …     3处未扫描              │
│ 大文件   ├───────────────────────┬─────────────────────────────┤
│ 操作历史 │ 名称        占用/状态 │ 所属应用 / 原始位置         │
│ 设置     │ ▸ 开发产物           │ 为什么发现 / 为什么保护    │
│          │ □ 文件A       …      │ 重建代价 / 最后修改时间     │
│          │ 🔒 文件B      …      │ [在Finder显示] [忽略此项]   │
│          ├───────────────────────┴─────────────────────────────┤
│          │ 已选 N项 / 估计… [取消选择] [预览计划]               │
└──────────┴─────────────────────────────────────────────────────┘
```

列表和可选矩形空间图使用同一聚合数据。v1必须有可用树表与排行，空间图属于可选增强，不得拖延扫描、错误解释或执行验收。

## 2. 页面

| 页面 | 必须显示/支持 | 不允许 |
|---|---|---|
| 首次启动/范围 | 本地处理说明、选择目录、明确范围；无自动开扫 | 要求先授予全盘权限才能进入 |
| 空间总览 | 卷可用空间、范围、扫描时间/覆盖、目录树/Top项、取消/重扫 | 全盘标完整但实际只扫Home |
| 清理候选 | 类别、归属、已知占用、规则/保护理由、能力标签“仅预览/可移入废纸篓/可永久清理缓存” | 锁定项可勾选、把关联数据统称垃圾 |
| 大文件 | 名称、位置、大小、修改时间、类型、排序/阈值、Finder定位 | 因文件旧就自动选中；标修改时间为“最后使用” |
| 计划预览 | 固定选中集合、动作、估计、排除数/理由、失效提示、确认按钮 | 混合Trash/Purge一个模糊“清理”按钮 |
| 执行与结果 | 逐项状态、当前/总数、停止后续项、成功/失败/待恢复、空间样本 | 静默吞错、取消后称全部撤销 |
| 操作历史 | 动作、时间、状态、摘要、恢复位置；可恢复项“恢复到原位置” | 给永久删除项显示撤销 |
| 设置 | 忽略管理、并发、保留策略、索引占用、权限缺口引导 | 自动关闭app、自动改系统权限 |

## 3. 选择和确认

- 每轮扫描选择为空；推荐项有建议标记，提供“选择当前可操作推荐项”，点击后显示具体数量与动作能力。
- 分组勾选只覆盖当前筛选中可操作项；有被隐藏项时提示“仅选择当前显示的N项”。组checkbox三态，保护项不计入可选分母。
- 改筛选不悄悄清除已选集合，底部提示“含N个当前未显示项”，计划预览显示全部选择。改变范围/规则/忽略后全部计划失效，选中ID需重新验证。
- 动作选择后，不能执行该动作的项从计划中拒绝并逐项说明，不自动转换动作。
- Trash确认：“将N个文件移入废纸篓；这一步通常不会增加可用空间。你可在操作历史恢复。”
- Purge确认：突出“永久删除N个缓存文件”，列根路径、类别、重建影响及未知估算；需用户勾选“我了解永久删除无法撤销”后才可点永久动作。
- 不提供“下次不再提醒永久删除”，也不保存跨重启确认。用户确认是每个计划一次，不是逐文件弹窗。

## 4. 异常与恢复文案

| 状态 | 文案要点 | 动作 |
|---|---|---|
| permissionDenied | “此处无法读取，结果不完整”，不显示为0 | 查看范围；授权后重新扫描 |
| activeOwner/activityUnknown | “应用正在使用/使用状态未能确认，已跳过” | 用户自行结束工作后重扫 |
| identityChanged | “扫描后文件已变化，未执行” | 重新扫描该范围 |
| rulesChanged/expired | “计划已失效，需重新预览” | 生成新计划 |
| restoreConflict | “原位置已有文件，已保留待恢复副本” | Finder查看两位置；不覆盖 |
| interruptedUnknown | “上次操作中断，结果待核实” | 对账/查看，禁止自动重删 |
| noCandidates | 区分“没有匹配候选”和“未能完成扫描” | 查看占用/权限缺口 |

操作完成显示“已处理X项，跳过Y项，失败Z项，待恢复W项”，同时显示每类动作；存在失败不能只用绿色大勾。空间变化为负或未增加时仍照实显示，并说明其他写入/快照可能影响，不能捏造释放值。

## 5. 交互与可访问性

- 键盘可切页、排序、选择、打开计划、取消；危险动作不绑定单次Delete键或默认Return。
- VoiceOver读出文件名、状态、是否可选、原因和单位；颜色不是唯一风险标识。
- 对外accessibilityIdentifier唯一且稳定：`scope.choose`、`scan.start`、`scan.cancel`、`results.table`、`plan.preview`、`plan.confirmTrash`、`plan.confirmPurge`、`operation.stop`、`history.restore`。行ID包含稳定entryID，不能所有按钮复用同一ID。
- 深浅色、长中文路径、零结果、十万级分页、最小窗口、缩放/减弱动态效果都要检查。
- “在Finder显示”只定位明确路径；不执行文件、不打开未知脚本。

## 6. 交付截图与用户路径

fixture模式使用应用本身的真实Store/Planner/Executor，输入根为测试创建目录；不能通过UI假数据开关绕过业务层。

需要留存：首次启动、扫描中、部分权限、混合保护候选、失效计划、Trash/Purge确认、混合结果、恢复冲突、历史。截图用于布局证明；文件manifest/journal用于行为证明。对真实用户目录截图留本地，外部交接使用合成fixture。
