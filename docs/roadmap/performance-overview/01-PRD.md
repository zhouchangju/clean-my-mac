# PRD：性能监控整合与菜单栏全局概览

版本 v0.1；PLANNED。本次设计基于用户讨论及现有源码，只定义后续行为，不表示已经实现。

## 1. 用户与问题

第一用户为项目所有者，使用 Apple Silicon Mac，频繁运行开发和 AI 工具。排查卡顿需要知道当前 CPU、内存与资源占用进程；整理存储需要知道当前剩余空间、既有空间分析结果及扫描进度。两个独立 App 增加切换、打包与维护成本。

主窗口适合深入操作，菜单栏入口适合随时快速查看。目标是用少量可靠指标回答“现在有什么值得进一步查看”，而不是承诺性能优化、生成笼统健康评分或复制商业软件全部功能。

## 2. 已确认范围与设计选择

用户已确认：以 clean-my-mac 为主，整合旧性能监控，考虑后续功能扩展，加入菜单栏概览；当前只交文档，待现有开发完成后实现。
建议设计：同一 App、按需采样、无后台常态轮询、macOS 14+、沿用既有 bundle ID 与数据位置。具体采样预算属于初始设计值，需开发验证，不是既有实测事实。

## 3. 典型用户路径

1. 感觉电脑慢：点击菜单栏图标 → 看 CPU/内存 → 点击卡片 → 主窗口性能页 → 按 CPU 或 footprint 排序查看进程。
2. 感觉空间不足：菜单栏查看实时可用空间 → 打开存储页 → 用户主动扫描 → 查看分类/大文件/计划；菜单面板自身不扫描、不执行清理。
3. 扫描进行中：关闭主窗口仍可查看菜单栏进度 → 返回任务页 → 用户在主窗口取消；关闭面板不取消扫描。
4. 同时打开面板与性能页：两处共享系统采样；仅详情页需要进程枚举。离开两个入口后停止性能周期采样。
5. 未来加入其他功能：模块提供自身快照、可用性和目的路由，概览组合展示，不改变清理内核。

## 5. 界面与交互

面板建议宽度约360–420pt，属于待实机验证的设计范围。CPU/内存、存储/任务按两列或自适应单列呈现；内容过长可滚动，不复制参考图中大面积营销区。
底部提供“打开主窗口”“设置”“退出”。卡片提供明确动作“查看进程”“查看存储”，不使用暗示已具备能力的“加速”“释放内存”。

顶部显示机器名称及“系统概览”，不计算综合 Good/Bad。每张卡有指标、单位、时效或状态。设备名称只本地显示。
主窗口新增性能导航，存储原有空间地图、建议、大文件、历史保持原工作流。错误有说明及重试入口；重试只重新测量，不触发清理或进程退出。
用户隐藏菜单栏入口后，主窗口设置可重新启用；不能失去唯一可达设置入口。首版默认不注册开机启动。

## 6. 数据口径与时效

系统 CPU 为0–100%的整体使用率；进程 CPU 以单核100%为口径，可超过100%，必须有说明。CPU 差值需要两次有效样本，首样本及睡眠唤醒后首样本未知。
内存 used/total 与 RSS、physical footprint 分别标注。footprint 缺失不得回退为虚拟内存并冒充已测；未采集 I/O/GPU 不显示0。
压力优先显示已验证的系统压力等级；没有可靠来源时显示“压力未取得”，不把内存占用百分比改名为压力。
启动卷 available 是当次系统 API 口径，不等同可清理量。存储扫描摘要沿用既有计量和未知规则，始终带扫描时间/终态，不能宣称完整覆盖。
初始时效阈值：CPU/内存6秒、空间30秒；超时保留旧值且显著标过期。扫描摘要独立标扫描时间，不以空间卡刷新让历史分类变新。

## 7. 生命周期与资源设计值

| 状态 | 系统 CPU/内存 | 进程列表 | 卷空间 |
|---|---|---|---|
| 概览打开 | 约2秒一轮 | 不采集 | 打开时及约10秒 |
| 性能页可见 | 共享约2秒采样 | 约2秒一轮 | 无需求不采集 |
| 两者可见 | 一份共享系统循环 | 一份详情循环 | 按概览需求 |
| 两者隐藏 | 停止周期采样 | 停止周期采样 | 停止周期查询 |
| 睡眠 | 暂停 | 暂停 | 暂停 |
| 唤醒且有订阅 | 重置差值后恢复 | 重置差值后恢复 | 刷新 |

主窗口遮挡、切页与应用焦点不是同一概念；菜单打开时不能沿用旧 isAppActive 判定阻止采样。采样超过间隔时不叠加，完成后再安排下一轮。详细设计和验收预算见技术方案与验收文档。

## 8. 非目标与后续方向

首版不做电池、温度、网络测速、外设弹出、杀毒、屏幕清洁、整体健康评分、常态告警、自动清理、退出进程、root/helper、云上传。
后续可以评估电池、网络、AI模型库存或其他用户明确需要的功能；这些是扩展例子，不是已授权实现范围。后台告警必须另定义持续采样、用户设置、去重与资源预算。未来退出进程需要独立操作资格与身份重验，不复用文件清理 Gate。

## 9. 阶段与完成标准

R0 当前开发交接与基线；R1 App外壳/功能隔离及只读采样；R2 性能详情与菜单概览；R3 原生验收、资源验证与制品交付。
18项验收均需对应版本证据。局部单元测试或构建成功不能代表菜单交互、系统指标准确或宿主资源表现通过。
