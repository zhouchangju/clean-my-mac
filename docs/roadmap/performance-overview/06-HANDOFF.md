# 开发交接与启动协议

## 当前仅文档

用户要求等当前进行的开发完成后再实施。本包交付不自动启动后续任务，不修改现有体验v2状态或标记原功能完成。

## 启动前 PO-01

读取届时最新体验v2 STATUS/ACCEPTANCE/DECISIONS、现有清理契约、工作区状态及本包。由原开发负责人交接停止重叠写入的文件范围、最终源码版本、实际验证和剩余缺口。
记录 baseline.md 到本包后续implementation子目录；尚无提交可用逐文件hash。不得将旧制品验证继承给新源码。当前开发未交接就保持WAITING，不同时拆其App或扫描模块。
只读扩展无需把原M2 BLOCKED改为PASS；保留其限制和真实缺口。本阶段不自动启动当前开发遗留工作。

## 总交接 Prompt

> 请依据 docs/roadmap/performance-overview/README.md 开发“性能监控整合与菜单栏概览”。先完成PO-01交接核查，确认当前开发已结束且无重叠写入；若未交接，只报告等待原因，不修改源码。以clean-my-mac主工程为准，保留现有清理契约、identity、数据路径及CLI。按05-TASKS依赖逐任务实现；首版只读性能详情和菜单概览，不做后台告警、进程退出、电池/温度或自动清理。每任务记录FR、AC、版本、实际测试结果和原始证据。未知指标保留未知，不通过虚拟内存/0填充或未发现进程推导安全。验收未过标FAIL/BLOCKED/UNVERIFIED，不用构建成功替代宿主行为。完成时提供同版本原生制品、关键验收及剩余限制；不自动安装、提交、发布或处理用户现有文件。

## 单任务交接

先读tasks/PO-xx.md和其依赖结果，再声明所负责文件、需求和验证范围。只在该范围实现；共享Shell/Package/App工程修改需串行协调，不能覆盖他人改动。
完成记录保存于后续implementation/PO-xx.md，至少包含需求/AC映射、源码版本、修改说明、命令与退出码、实际发现测试数/skip、宿主结果、证据路径及未覆盖项。
后续可以任务分工，但不能仅凭依赖表就并发修改相同文件；本包没有自动启动代理或执行脚本。

## 停止与恢复

重复采样、资源超预算、数据误导或storage回归时先停止扩展，保留失败证据，回到最近通过的代码边界。源监控项目保持完整，验收前不删除。
阻塞不豁免验收；无法取得压力来源可通过明确unknown满足FR-04，不能把所有采样缺失都视为功能完成。主机不可用则原生AC保持UNVERIFIED。
任务取消不清理用户文件；本轮所有变更型验证仅自建fixture。已有清理恢复继续使用原契约，概览不会自行恢复/删除。

## 本包优先级

PRD定义范围；技术方案定义协作语义；验收定义完成证据；目录文档指导迁移；子任务不能降低前三者要求。本包与原清理契约冲突时先记录冲突，保留更严格的操作边界并修订设计，不绕过Gate。
